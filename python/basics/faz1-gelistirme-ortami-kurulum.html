Python + VS Code + venv
kurulumu

IoT / Embedded / Drone geliştiricisi gözünden sıfırdan kurulum. Sadece "Python yükle" değil — sahada cihaza deploy eden, seri porttan sensör okuyan bir geliştiricinin kurması gereken temel.

Stack: Python 3 · pip · venv Editör: VS Code + PlatformIO Hedef: Arduino · RPi · MQTT

◇ Neden bu kurulum, neden bu sıra?

Bir web geliştiricisi tek makinede çalışır. Sen ise iki dünyada yaşayacaksın: kodu Windows/Mac'te yazıp, onu başka bir donanıma (Raspberry Pi, ESP32, drone uçuş kontrolcüsü) gönderirsin. Bu yüzden kurulumun temel hedefi taşınabilirlik ve tekrarlanabilirlik.

İşte bu yüzden venv opsiyonel değil zorunlu: her projede farklı kütüphane sürümleri (pymavlink, pyserial, paho-mqtt) pinlersin ve aynı ortamı cihazda birebir yeniden kurabilirsin.

1

Python 3 kurulumu

Yorumlayıcı + pip + PATH

IoT'de Python iki rol üstlenir: prototipleme dili (Raspberry Pi, sensör testi, MQTT) ve araç dili (pymavlink ile drone telemetri, KiCad scriptleri). Faz1'in ana dili budur.

  1. python.org/downloads adresinden son 3.12.x sürümünü indir (3.13 çok yeni; bazı IoT kütüphaneleri henüz uyumlu olmayabilir).
  2. Yükleyiciyi açtığında en alttaki kutuyu mutlaka işaretle: "Add python.exe to PATH". Bu adım %90 kurulum derdinin kaynağıdır.
  3. "Install Now" → bitince yeni bir PowerShell aç ve doğrula:
PowerShell
PS> python --version
# Python 3.12.x görmelisin
PS> pip --version
Dikkat
'python' is not recognized hatası alırsan PATH işaretlenmemiştir. Yükleyiciyi tekrar çalıştır → Modify → PATH kutusunu işaretle.
  1. Raspberry Pi OS / Ubuntu ile Python 3 zaten kuruludur — ama komut python3'tür, python değil.
  2. Eksik araçları tamamla (venv ve pip dahil):
bash · Debian/Ubuntu
$ sudo apt update && sudo apt install python3 python3-pip python3-venv
$ python3 --version
IoT notu
Pi üzerinde GPIO/sensör erişimi için ilerde gpiozero, RPi.GPIO, pyserial kuracaksın — ama sistem Python'ına değil, venv'e. Sistem Python'ını kirletirsen apt güncellemeleri bozulabilir.
  1. Apple'ın sistem Python'ına dokunma. Homebrew ile istediğin sürümü kur:
  2. macOS'ta her sürümün kendi numaralı komutu olur (python3.12, python3.14 gibi) — Windows'taki py başlatıcısının karşılığı budur. py komutu macOS'ta yoktur.
zsh · Homebrew
$ brew install python@3.12
$ python3.12 --version   # sürümü adıyla çağır, garanti olsun
macOS notu
Apple Silicon'da Homebrew yolu /opt/homebrew/bin, Intel Mac'te /usr/local/bin'dir. python3.12 --version çalışıyorsa kurulum tamamdır — bare python3'ün ne dediği önemli değil (aşağıdaki teşhis kutusuna bak).

⚠ "python --version yanlış sürüm gösteriyor" — neden ve çözüm

3.12 kurdun ama python --version sana 3.14 diyor? Bu bir hata değil. Makinede birden fazla Python var ve python3 komutu PATH'te ilk gördüğünü çalıştırıyor — o da daha yeni sürüm. Önce ne olduğunu gör:

zsh · teşhis
$ which -a python python3   # PATH'teki tüm eşleşmeler — en üstteki kazanır
$ python3 --version        # şu an hangisi seçili
$ python3.12 --version     # 3.12 gerçekten kurulu mu?
macOS notu
py --list Windows'a özgüdür, macOS'ta yoktur. Burada sürümü numaralı komutla (python3.12) seçersin. python3.12 --version "command not found" derse 3.12 kurulu değildir → brew install python@3.12.
PowerShell · teşhis
PS> py --list          # kurulu TÜM sürümler + yolları
PS> where python       # hangi python.exe kazanıyor (ilk satır)
Çözüm
PATH'le uğraşma. Sürümü venv yaratırken sabitle — venv kendi yorumlayıcısını içine kilitler, sonra global python3 ne derse desin (venv) içinde doğru sürüm çalışır:
• macOS / Linux: python3.12 -m venv venv
• Windows: py -3.12 -m venv venv
İkisi de aynı mantık; sadece komut adı farklı. Eski sürümü silmene gerek yok, yan yana dururlar.

VS Code + IoT eklentileri

Editör · Embedded toolchain · Uzak cihaz

code.visualstudio.com → indir, kur. VS Code'u IoT için güçlü kılan editörün kendisi değil, doğru eklentiler. Soldaki Extensions (⌃⇧X / Ctrl+Shift+X) panelinden ara ve kur:

Python Microsoft
Yorumlayıcı seçimi, debug, IntelliSense. Olmazsa olmaz. Pylance otomatik gelir.
PlatformIO IDE
Faz2'nin (STM32 / ESP32 / Arduino) endüstri standardı toolchain'i. Şimdiden kur — Arduino IDE'ye göre çok daha profesyonel; kütüphane yönetimi + derleyici + upload tek yerde.
Remote – SSH Microsoft
Raspberry Pi'ye SSH ile bağlanıp doğrudan üzerinde kod yazarsın. Headless (ekransız) Pi geliştirmenin tek mantıklı yolu.
Serial Monitor Microsoft
Arduino/ESP32'den gelen seri çıktıyı VS Code içinde izlersin. Sensör debug'ının kalbi.
C/C++ Microsoft
Faz2'de STM32/FreeRTOS C koduna geçince gerekecek. Şimdilik kur, beklesin.
IoT notu
VS Code'da bir .py dosyası açıkken sağ altta Python yorumlayıcısını seç. Buraya birazdan oluşturacağın venv'i seçeceksin — böylece Run/Debug doğru ortamı kullanır.

Terminal temelleri

Dosya gezinme · Entegre terminal · SSH

IoT'de fare ile tıklayarak cihaz yönetemezsin — Pi'ye ssh'larsın, paket kurarsın, log okursun. Terminal senin birincil arayüzün. VS Code'da Terminal → New Terminal (⌃` / Ctrl+`) ile editörün içinden açılır; ayrı pencereye gerek yok.

Hayatta kalma komutları

temel navigasyon
pwd              # neredeyim? (Windows: cd)
ls               # klasör içeriği (Windows: dir)
cd projeler/iot  # klasöre gir
cd ..            # bir üst klasöre çık
mkdir drone-test # yeni klasör oluştur

Cihaza bağlanmak (IoT'nin günlük rutini)

bash · Raspberry Pi'ye SSH
$ ssh pi@192.168.1.42     # Pi'nin IP'si ile bağlan
# Artık tüm komutlar Pi üzerinde çalışır
$ exit                   # bağlantıyı kapat
IoT notu
Pi'nin IP'sini bilmiyorsan, ağdaki cihazları ping raspberrypi.local ile veya router arayüzünden bulabilirsin. SSH'ı Pi'de Raspberry Pi Configuration → Interfaces'ten aktif etmen gerekir.
4

Sanal ortam (venv)

İzolasyon · Tekrarlanabilirlik · Deploy

◇ venv tam olarak neyi çözer?

Diyelim tarım dronu projen pymavlink 2.4 istiyor, ama eski bir sensör projen başka bir sürüme bağımlı. Global kurarsan biri diğerini bozar.

venv = her projeye kendine ait, izole bir Python kutusu. Projeyi cihaza taşıdığında requirements.txt ile birebir aynı ortamı saniyeler içinde yeniden kurarsın. Endüstriyel/savunma projelerinde bu tekrarlanabilirlik bir lüks değil, gerekliliktir.

Adım 4.1 — Proje klasörü oluştur ve gir

terminal
mkdir iot-faz1 && cd iot-faz1

Adım 4.2 — venv'i oluştur (doğru sürümle)

Klasörün içinde venv adında izole ortam yarat. Hangi Python sürümünü istiyorsan onu adıyla çağır — böylece yukarıdaki "yanlış sürüm" sorunu hiç yaşanmaz:

terminal
# macOS / Linux — sürümü adıyla sabitle:
python3.12 -m venv venv

# Windows — py başlatıcısı ile:
py -3.12 -m venv venv

Adım 4.3 — Ortamı aktifleştir

PowerShell
PS> .\venv\Scripts\Activate.ps1
Sık hata
running scripts is disabled hatası → PowerShell scriptlere kapalıdır. Tek seferlik şunu çalıştır:
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
CMD kullanıyorsan komut farklı: venv\Scripts\activate.bat
bash / zsh
$ source venv/bin/activate

Başarılıysa satır başında (venv) görürsün. Artık bu terminaldeki her pip install yalnızca bu projeye gider.

Adım 4.4 — IoT kütüphanelerini kur

(venv) aktifken
(venv) $ pip install pyserial paho-mqtt
# pyserial  → Arduino/sensör ile seri haberleşme
# paho-mqtt → MQTT broker'a publish/subscribe

Adım 4.5 — Ortamı dondur (deploy'un anahtarı)

Kurduğun her şeyi sürümleriyle bir dosyaya yaz. Cihaza geçtiğinde bu dosya ile her şeyi tek komutta kurarsın:

(venv) $
(venv) $ pip freeze > requirements.txt   # mevcut ortamı kaydet

# --- başka makinede / Pi'de yeniden kurmak için: ---
(venv) $ pip install -r requirements.txt

Adım 4.6 — Çıkış

terminal
(venv) $ deactivate            # ortamdan çık

Adım 4.7 — venv'i .gitignore'a ekle

◇ Neden venv'i Git'e koymuyoruz?

venv klasörü yüzlerce MB tutabilir, makineye ve işletim sistemine özeldir (Mac'te yarattığın venv Pi'de çalışmaz) ve zaten requirements.txt'ten saniyeler içinde yeniden üretilebilir. Repo'da paylaşılması gereken tek şey kaynak kodun + requirements.txt'tir.

Proje kök klasöründe (venv'in yanında) .gitignore adında bir dosya oluştur. Terminalden tek komutla yapabilirsin:

terminal · .gitignore oluştur
# proje kökünde, venv'in yanında:
cat > .gitignore << 'EOF'
# --- Python / venv ---
venv/
.venv/
__pycache__/
*.pyc

# --- editör / OS ---
.vscode/
.DS_Store

# --- IoT: gizli bilgiler ASLA commit edilmez ---
.env
secrets.py
*.pem
config_local.py
EOF
IoT notu
Son blok kritik: MQTT broker şifresi, Wi-Fi parolası, API anahtarı veya drone telemetri token'ı gibi sırları koda gömme; .env dosyasına koy ve onu da gizle. Açık repo'ya yanlışlıkla sızan bir cihaz parolası sahada gerçek bir güvenlik açığıdır.

Doğru çalıştığını teyit et — venv/ artık Git'in göreceği listede olmamalı:

terminal · doğrula
$ git init                # repo henüz yoksa
$ git status              # 'venv/' listede GÖRÜNMEMELİ
Geç kaldıysan
venv'i .gitignore'dan önce commit'lediysen, ignore tek başına yetmez — Git onu zaten takip ediyordur. Takipten çıkar:
git rm -r --cached venv → ardından commit'le. Dosyalar diskte kalır, sadece Git'in takibinden düşer.
